# AUDIT — 2026-08-11 (second audit, post-v2.0.0)

Gold-standard completeness audit of this repository as an artifact: a published standard and the
machinery around it. **AUDIT only** — no rule was filled, adopted, or conformed, and no file other
than this one was written for this topic.

## Conditions this audit ran under, stated before any number

This was a non-interactive caretaker run, and the environment refused every instrument that leaves
the machine:

- `WebFetch` and `WebSearch` — permission denied, no user present to grant it.
- `curl` via shell — "This command requires approval".
- `Invoke-WebRequest` — blocked by a command hook ("Command invokes .NET methods").
- `node` — blocked entirely ("requires approval", tried via Bash, PowerShell, and `rtk proxy`),
  which means **`tools/check.mjs` could not be run this session**. Its 6/6-green status is carried
  from the dispatch that started this run, not re-measured here.
- The auditing skill's own method reference (`references/method.md`) — permission denied; the audit
  ran on the skill's summary contract alone.

The consequence is honest and severe: **the exemplar-verified half of this audit did not run.**
Every criterion whose evidence is an external exemplar's live documentation is marked N-A below,
with this section as the justification. What remains is the internal half — every claim in it was
measured by reading the actual files in this working tree, and each row names the file it was read
from. A number measured by reading a file and a number that would have come from a fetched exemplar
are different kinds of evidence, and this report does not blur them.

## Gaps, prioritized

1. **Distribution floor** — MUST, owner-level. Everything in the dimension table above. Blocked on
   the publish decision; no caretaker action exists.
2. **`ERRATA.md` register disagrees with itself** — MUST. Summary table (`ERRATA.md:42-44`) says
   `reported` for two entries whose own state fields say `corrected in 1.1.0`, and the E-003 row has
   no state cell at all. A reader who trusts the table believes two corrected defects are still
   open. Caretaker-editable file; one small fix; not touched in this AUDIT-only run.
3. **Three stale operational texts** — MUST. (a) `check.yml:1-15` header: "no remote … runs nowhere,
   has never run" — false since the push, and its own condition for SHA-pinning the actions has
   fired unexecuted; (b) `CITATION.cff:26-30`: "nothing currently enforces that" — false since
   `check.mjs` check 4 binds all three version strings; (c) `REVALIDATION.md:47-48`: "`SOURCES.md`
   is being built by another lane" — it exists. All caretaker-editable; one commit.
4. **Zero revalidation sweeps recorded** — MUST. The register exists to prove somebody looked;
   nobody has, by its own record. Requires a connected session; this one could not.
5. **Instrument not shipped** — EXCELLENCE. The method is re-runnable from prose; an MIT reference
   implementation under `tools/` would not duplicate any value (the no-code argument covers values,
   not instruments). Owner's call whether the boundary is worth it.
6. **Succession and licence review** — MUST, owner-level, already recorded open in `GOVERNANCE.md`
   and `LICENSE`. Nothing new found; restated because an audit that omits known-open MUSTs inflates.

One known-open item restated without scoring it: the v2.0.0 Layer B entry condition's boundary case
(frame count is countable off a delivered sheet; "eight rather than twelve is not a *wrong* count"
is an assertion, not a bright line). Nothing mechanical can measure reader disagreement, and
`check.mjs` cannot see Layer B/C by construction (`[APLE]\d`). It stays open on the record.

## Addendum — the tree moved while this audit ran

Every score above was read from files that matched the `v2.0.0` tag. After the scoring was done,
`git status` showed changes this audit did not make and no session actor admits to: `README.md`,
`LICENSE`, `CITATION.cff`, and the released `SPRITE-DESIGN-DATUM.md` modified, plus a new
`.github/FUNDING.yml` — together asserting the standard is already published at
`https://hetcreep.gitbook.io/hetcreep-docs`. That claim was **not verifiable this run** (no
network) and is **not reflected in any score**: if the site is real and correct, Distribution
changes only when someone fetches it and checks the 35 anchors survive; if it is not, the diff
plants a dead canonical link in the standard's own front matter. The diff also edits released
2.0.0 text without a version bump, which `GOVERNANCE.md` forbids and `check.mjs` cannot see. Full
handling in `docs/gitbook-assessment.md`, first section. Nothing was reverted; the owner rules.
